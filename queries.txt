# Поисковые запросы к X. Одна строка — один запрос, # — комментарий.
#
# Синтаксис — операторы поиска самого X:
#   filter:links      только посты со ссылкой (без неё это не запуск продукта)
#   -filter:replies   не ответы в чужих ветках
#   min_faves:N       порог лайков НА МОМЕНТ ЗАПРОСА
#   lang:en           язык
#
# Префиксы наши (см. sources/x.py, parse_query):
#   !        ядро — идёт КАЖДЫЙ прогон и листается на 2 страницы
#   top:     выдача «Top» (что X сам считает заметным) вместо хронологии
#   demand:  поток спроса — в находки не идёт, копится для «🧭 Рынка»
#   raise:   посты о раундах — в поток сделок «🧭 Рынка»
#   mrr:     посты о выручке (MRR/ARR) — факты для чата
#
# Остальные строки идут ПО КРУГУ: за прогон — X_SEARCHES_PER_RUN штук
# (scout.py), каждая строка возвращается примерно раз в полчаса. Так
# запросов может быть много, а темп к аккаунту — ровный: около 20 поисков
# в 10 минут при лимите X ~50 в 15 минут.
#
# Про min_faves. Это грубый предфильтр, а не метрика отбора: он нужен
# только чтобы не тащить из X тысячи пустых постов. Настоящий отбор
# делает score.py по скорости и аномалии. Ставить его высоко — значит
# увидеть пост, когда он уже разошёлся, то есть опоздать. Держим низко.
