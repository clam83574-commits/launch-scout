# launch-scout — радар рынка для стартаперов в Telegram

Две вещи в одном боте:

1. **🧭 Рынок** — куда идут деньги инвесторов, по секторам и в цифрах: число,
   сумма и стадии раундов, ниши с ранними раундами, доля сектора в батчах
   YC, запросы людей. Не «что лайкают», а «куда смещается рынок» — например, доля
   физического продукта (железо, роботы, оборона, энергетика, логистика) в
   YC: 16–23% год назад против 38–41% в двух последних батчах.
2. **🔥 Находки** — продукты в первые часы после выхода, оценённые по
   скорости отклика против всей площадки, а не по абсолютным цифрам.

Каждый подписчик сам решает, что ему присылать: секторы, источники, порог
находок и пять видов уведомлений (`⚙️ Настройки` в чате или в приложении).

Контекст, решения и юридические флаги — в `SOFTWARE.md`, запись `launch-scout`.
Здесь только как этим пользоваться.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
```

Дальше заполнить `.env` (подробности — прямо в комментариях того файла):

| Ключ | Обязателен | Зачем |
|---|---|---|
| `TG_BOT_TOKEN`, `TG_CHAT_ID` | да | иначе находки некуда слать |
| `X_AUTH_TOKEN`, `X_CT0` | нет | без них работают три источника из четырёх |
| `GITHUB_TOKEN` | нет | поднимает лимит с 10 поисков в минуту до 30 |

## Запуск

```bash
python scout.py --dry          # прогон без отправки, посмотреть что нашлось
python scout.py                # боевой прогон (его и ставить на расписание)
python scout.py --digest       # добавить к прогону сводку по накопленному
python scout.py --top 10       # прислать 10 лучших ПРЯМО СЕЙЧАС, минуя пороги
python scout.py --status       # что в базе, кто из источников молчит
python scout.py --sources hn,yc   # только выбранные источники
python bot.py                  # бот с кнопками (висит постоянно)
python setup_chat.py 900       # поймать chat_id: напишите боту, он запишет сам
python test_score.py           # проверка формулы оценки на подставных данных
python test_market.py          # проверка разбора раундов и импульса секторов
python market.py --refresh     # пересчитать рынок и показать отчёт в консоли
```

Два режима работают одновременно и не мешают друг другу:

- **само** — задача планировщика раз в 25 минут шлёт то, что перевалило порог;
- **по требованию** — кнопки в боте: «🔥 Топ-10», «🔄 Обновить сейчас»
  (идёт в источники прямо сейчас и показывает найденное), «🆕 За сутки»,
  «📊 Статус».

Выдача по требованию порог НЕ применяет: на вопрос «покажи, что есть» ответ
«ничего не дотянуло до 58» бесполезен. Зато она сворачивает дубли по домену —
иначе десятка мест уходит на один продукт, замеченный в трёх источниках.

Бот закрытый: владелец — по id, остальные — по коду доступа (пишут код
одним сообщением, дальше он не нужен). Перебор заперт: пять промахов
закрывают чат на час. Как выдать и отобрать доступ — `deploy/RUN.md`.

**Первый прогон — посевной.** Он записывает всё, что видит, и НЕ шлёт ничего:
иначе запуск системы означал бы залп из семисот сообщений про компании,
накопленные в каталоге YC за годы. Уведомления начинаются со второго прогона,
и приходят только на то, что появилось после него.

Расписание и автозапуск: `deploy/RUN.md`.

| Источник | Ключи | Что даёт | Задержка от события |
|---|---|---|---|
| **X (Twitter)** | куки аккаунта | посты о запусках, лайки/ответы/**закладки**, ленты выбранных аккаунтов | минуты |
| **Hacker News** | не нужны | `Launch HN` (так запускаются компании YC) и `Show HN`, очки и комментарии | минуты |

## Рынок: как считается «куда движется»

`market.py`. Опора — только ВНЕШНИЕ данные: деньги инвесторов, отбор YC,
запросы людей. Наши собственные находки в расчёт рынка не входят
(2026-09-28): доля сектора среди того, что прошло наши же фильтры, —
зеркало фильтров, а не рынка.

**Раунды — главный сигнал.** Откуда: Google News по каждому из 16 секторов
(два окна по 14 дней) и общими запросами по стадиям, ленты TechCrunch
Venture и EU-Startups, посты основателей в X (`raise:` в queries.txt).
Каждый заголовок разбирает ИИ (Groq, gpt-oss-120b; очередь по 40 заголовков
за прогон): раунд ли это вообще, чей, сумма в долларах, стадия, сектор,
ниша и что делает компания. Одна сделка в пяти изданиях склеивается в
один раунд по названию компании (`market.rounds`).

| Опора | Что считается | Вес |
|---|---|---|
| 💰 Деньги | изменение **доли** сектора в общем потоке раундов | 0.45 |
| 🌱 Ранние раунды | то же только по pre-seed, seed и A | 0.20 |
| 🎓 Отбор YC | доля сектора в последнем батче против среднего трёх прошлых | 0.25 |
| 🙋 Спрос | посты в X «сделайте кто-нибудь…», «заплатил бы за…» | 0.10 |

Импульс ≥ 0.35 — «растёт», ≤ −0.3 — «остывает». Доля, а не сырое число:
Google News полнее индексирует свежие статьи, и по сырому числу «рос»
каждый второй сектор. Поэтому сектор может «остывать» при росте числа
раундов — если весь поток вырос сильнее; это написано прямо в отчёте.

**💡 Ниши** — ответ на «какая идея сейчас залетает». Ниша (её называет ИИ:
кто клиент + какая работа, например «insurance claims automation») попадает
в отчёт, когда за 28 дней в ней подняли раунды хотя бы три разные
компании. Ранние раунды важнее поздних: три seed-раунда — ниша
открывается, три раунда C — места поделены.

Рассылки: 🧭 рынок недели (понедельник, 10:00 МСК), 💰 раунды за сутки по
секторам подписчика (по разу на компанию), 🚀 сдвиг — сектор впервые
перешёл в рост, 💡 ниша впервые набрала 3 раунда, из них 2 ранних.

Пересчёт раундов — раз в 6 часов, каталог YC — раз в сутки, отчёт — после
каждой разобранной пачки. `python test_market.py` проверяет разбор,
склейку дублей, стадии и ниши.

**Связка с находками.** Если у компании из находки есть свежий раунд
(совпадение по имени из каталога YC, Launch HN или домену), она получает
до +20 баллов и строку «раунд инвесторов: $6 млн, seed» в разборе.

## Как считается балл

Абсолютные числа не значат ничего: 500 лайков — это тишина у аккаунта на
200 тысяч подписчиков и событие у аккаунта на восемьсот. Поэтому считаются
три вещи, которых не видно глазами.

1. **Скорость и ускорение.** Сколько набирает в час и растёт ли темп.
   Ради этого замеры хранятся историей, а не последним снимком: пост,
   который ещё разгоняется, ценнее того, что уже собрал больше и встал.
2. **Аномалия относительно автора.** Отклонение от его собственной нормы
   (медиана последних постов, разброс через MAD, а не через сигму —
   у вовлечённости тяжёлый хвост, и один вирусный пост раздувает сигму так,
   что следующий вирусный выглядит нормой). Ловит момент, когда у человека,
   которого обычно не замечают, вдруг выстрелило.
3. **Качество внимания.** Доля закладок к лайкам. Лайк ставят за остроумие,
   в закладки кладут то, к чему собираются вернуться, — это отличает
   инструмент от развлечения лучше любой другой бесплатной метрики.

Плюс: свежесть домена по RDAP, подтверждение из другого источника, факт
отбора в YC. Минус: спор в комментариях вместо одобрения, «про это пишут
вторую неделю» (окно закрылось), запретные и пограничные ниши.

Разбор баллов приходит в самом сообщении — порог должен быть объясним,
иначе непонятно, что крутить, когда выдача поедет.

Пороги: **58** — мгновенное сообщение, **42** — в сводку, ниже — лежит в базе.
Менять в `score.py`, `HOT_MIN` / `DIGEST_MIN`. После правки —
`python test_score.py`: он проверяет, что пороги вообще достижимы (первая
версия была выставлена так, что мгновенное уведомление не могло сработать
в принципе).

**Порог уведомления (2026-09-28).** Мгновенное уведомление — только при
реальном отклике в абсолютных числах: от 40 очков на HN, 100 лайков в X,
250 звёзд на GitHub (`PUSH_FLOOR`) — или при подтверждённом раунде
инвесторов. Launch HN больше не приходит «горячим» за сам факт поста
(раньше 60 баллов без единого очка). Ниже порога отклика (20 / 30 / 150)
находка не идёт даже в сводку. Каталог YC без раунда — только сводка.

**Порог отклика (2026-09-28).** Сравнение «быстрее N% площадки» и темп
считаются только от 20 очков на HN, 30 лайков в X и 150 звёзд на GitHub;
до 40 очков / 150 лайков / 300 звёзд — вполовину. Раньше пост с шестью
очками через двадцать минут после публикации получал «быстрее 100% постов HN»
(+52) — ровно такие «взлёты» и приходили. Теперь в разборе всегда видно
абсолютное число: «60 очков за 6 ч — быстрее 99% постов HN». Launch HN
по-прежнему приходит в день запуска без отклика, но с пометкой
«⏳ отклика пока нет — это сигнал о запуске, а не о взлёте».

## Настройка под себя

- `accounts.txt` — чьи посты читаются целиком, без фильтра по маркерам
  запуска. После правки: `python scout.py --init-accounts`.
  Список ценен прополкой, а не длиной: сорок проверенных аккаунтов
  работают лучше двухсот случайных.
- `queries.txt` — поисковые запросы к X с их родными операторами. Строка
  с `!` идёт каждый прогон на две страницы, `top:` — выдача «Top» вместо
  хронологии, `demand:` — поток спроса для рынка; остальные — по кругу,
  по 12 за прогон (`X_SEARCHES_PER_RUN` в scout.py).
  `min_faves` там — грубый предфильтр, чтобы не тащить тысячи пустых
  постов, а не метрика отбора; ставить его высоко = видеть пост, когда он
  уже разошёлся.
- `score.py` — веса слагаемых и списки ниш (`HARD_BLOCK` режет,
  `SOFT_FLAG` помечает и снимает баллы, решение остаётся за человеком).

## Чего здесь ещё нет

- Product Hunt: API бесплатный, но требует токена через OAuth — не заведён.
- Telegram-бот для просмотра базы (сейчас только исходящие уведомления);
  каркас для него есть готовый — `products/tm-scout/worker`.
- SEC EDGAR Form D — официальное подтверждение привлечённого раунда с
  суммой. Бесплатно, но с задержкой до 15 дней и только по США.
- Дифф портфолио фондов: страницы a16z, Sequoia и Accel рисуются
  джаваскриптом, их внутренние JSON закрыты (проверено 2026-09-20) —
  нужен headless-браузер, как в tm-scout.
- Проверка «есть ли русскоязычный аналог» — то, что превращает ленту
  чужих запусков в список идей, которые можно забрать на своём рынке.
